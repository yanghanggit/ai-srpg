# 上下文窗口管理（Context Window Management）

## 意图

角色与舞台的 agent 记忆随回合单调累积，上行 prompt 持续膨胀，最终逼近模型上下文上限。当前有三样东西：占比信号、压缩动作、按占比自动安排压缩。

## 上下文占比

模型响应后，token 用量占模型上下文窗口的比例写入该 agent 的记忆，并随 AI 回复消息一起同步。占比只是「这个 agent 有多满」的信号，不承载策略；读取方据此决定是否压缩。

占比只来自真实模型响应；接管等不经过模型的决策不会伪造这个信号。占比是否足够新，是压缩策略要面对的问题，不由记忆写入方补一个假值。

## 自动触发

每轮先由收集端检查各 agent 的占比，超过阈值就替它挂上压缩动作；随后消费端在同一次 pass 里完成折叠。两个 system 分开，是为了让「何时压」随玩法调整，而「怎么压」保持唯一。

压缩排在计划系统之前：它折的是「这一轮开始时的记忆」，本轮新产生的消息不会被当轮吞掉；放到管线尾部则会立刻吃掉刚发生的事。

阈值是运营口径而非机制，写死在收集端一个常量里；随着模型上下文变大，它可能长期不触发，也就不必担心误伤。

## 压缩原语

压缩把首条 system prompt 之外的消息替换成一条摘要，保留显式标记为压缩保留的消息，并把占比归零。它现在也是一个动作：由一个 system 在同一次 pass 里消费，因此压缩失败会随整次 pass 一起回滚，不会停在折叠了一半的记忆上。手动入口只是把动作挂上去。何时自动触发、阈值多少属于玩法规则，待规则层定义。

压缩只保留首条 system prompt 与显式保留项。绝大多数事实型记录（胜负、阵亡等）只属叙事，允许被摘要吞掉——它们的权威载体是组件，记忆只负责让人记得大概发生过什么。

## 作用域

压缩是记忆层的操作，不改变 ECS 组件；ECS 与记忆是平级系统，各自管理自己的状态。它进 pipeline 而不是绕过去，原因与其它状态改动相同——改记忆必须发生在知道「这是哪一轮」的地方。自动触发策略缺失期间，需要时由调用方挂这个动作。
