# SRPG AI 操作 CLI（ai-srpg-agent-game）

## 定位

`ai-srpg-agent-game` 是离线、快照驱动的游戏开发辅助入口：一次调用只完成一个动作，世界状态由 PostgreSQL 的 `game_snapshots` 承载，命令之间不保持进程内状态。它用于规则回归、问题复现与逐步观察 ECS 状态；需要走真实 HTTP 契约时改用与服务端同契约的客户端。

→ 参见：[会话历史（Session History）](session-history.md)
→ 参见：[服务端客户端（ai-srpg-client）](run-game-client.md)

## 状态模型

每局游戏由「用户 + 游戏名」标识，快照只追加、不原地更新；最新状态是 id 最大的快照，指定 `--snapshot-id` 可回到历史点。CLI 每次从蓝图或快照重建游戏实例，因此任何需要保留的变化都必须在动作结束时写回快照。

`new` 写入基线快照。`advance` 在执行前写一条快照用于失败回滚，成功后再追加结果快照；`compact-context` 在压缩成功后追加结果快照。失败回滚只影响内存中的 ECS 与 agent 记忆，不会删除执行前那条快照。

→ 参见：[System 错误处理与回滚边界](system-error-handling.md)

## 命令面

`list` 列出该玩家的所有对局，按最近更新倒序，给出快照条数与最新快照 id——先看清手上有哪些局，再决定对哪一局动手。

命令之间不隐式串联：`new` 只装配世界，`bind` 只改绑定，二者可单独使用，也可任意组合。

`new` 从 `.blueprints` 下的蓝图创建新局：没有快照时构建并初始化，已有快照时默认报错；`--reset` 会从蓝图重建并追加新的基线快照，旧历史保留。建局不涉及玩家，蓝图也不声明谁可玩。

`bind` 让该玩家接管一个已有角色，`--actor` 指定角色名，成功后追加结果快照；没有对局时报错而不隐式建局。接管只看 ECS 里已有的角色，不推进时间——它是入场前的一次配置，与正式游戏里「开局前就把席位绑定好」是同一件事，只是开发期需要能随时改。

`snapshots` 按时间倒序列出快照 id、创建时间、实体数与记忆数，用于确认动作是否落库以及选择回滚点。

`stages` 读取指定快照并输出「舞台 → 角色」映射，`--json` 供脚本消费。

`compact-context` 给目标实体挂上压缩动作并跑一次 pass（因此与其它推进一样有回滚点），可选 `--summary` 指定折叠后的摘要；目标必须有 system 起始的 agent 记忆。

`actors` 列出角色名册：所在位置、控制者与当前外观，`--json` 供脚本消费——先看有谁，再决定推谁。

`plan` 给一个或多个角色做本轮计划：`--actor` 可重复，每次点名一轮；计划只挂动作，成效由后续的行为 system 在同一 pass 内完成。

`act` 接管一个角色：给一条命令（说话、大地图移动、进入地点、离开地点、区域内移动、原地不动），跑一次 pass 后回报执行后所在的位置。命令与自主计划共用同一套前置条件与同一份记忆形状；默认只能命令自己绑定过的角色，`--force` 跳过绑定校验。

`memories` 把记忆导出成 markdown，一个实体一个文件，落在 `logs/memories/<用户>-<游戏>-<时间>/` 下（`--dir` 可改目录）：文件名就是实体全名，文档只有一层标题，消息按发生顺序编号并标出类型，工具调用接在正文后面。消息正文一律放在代码块里，所以提示词自带的标题与列表不会和文档结构打架，读到的就是原样文本。`--entity` 可重复，只导指定实体——排查某个角色为什么这么说时，比翻调用记录快。导出只读，不产生快照。

`advance` 加载指定快照、执行一次完整 pass，并输出是否完成、实际运行与跳过的 processor，以及结果快照 id。

读取状态的命令统一用 `--user` / `--game` 定位对局；`--snapshot-id` 缺省时使用最新快照。

调用观测命令：`llm-calls` 按时间倒序列出最近调用，可按标签、用户、游戏、命令、agent loop、轮次、`cli`/`room` 作用域与时间范围过滤，也可输出 JSON 供脚本分析；`llm-call` 按完整 id 或唯一前缀展开一次调用，包含系统提示、历史消息、AI 回复、工具调用、推理过程、错误信息与调用来源。

记录随调用附带分析维度：用户、游戏、命令、快照标识、job 标识、agent loop 与轮次、agent/entity 名称，以及调用开始时间与上下文占比。文件按作用域切分：CLI 每次进程独立目录，服务端按房间独立目录；`make clean-llm-calls` 可整体清空，不做保留策略。

## 职责分层

Click 层只做参数解析、日志初始化与输出；动作编排在 `ai_srpg/srpg_game_agent/`。离线状态入口放在玩法编排层，负责蓝图/快照的读取与保存；pass 的快照与回滚语义与后台 job 共用，CLI 不重复实现执行规则。

→ 参见：[Job 执行与事件日志（Job Execution）](job-execution.md)
